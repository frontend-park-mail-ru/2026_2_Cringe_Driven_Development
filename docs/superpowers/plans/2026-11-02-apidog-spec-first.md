# Spec First и Cloud Mock Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Агент перед работой с Go API проверяет актуальный Apidog и использует Cloud Mock; дефекты мока исправляются отдельным MR в Apidog.

**Architecture:** Короткое обязательное правило в AGENTS.md ведёт в `docs/api-contract.md`, где хранится подробный порядок Spec First. Из инструкции локального запуска на этот порядок ведёт ссылка. Код и конфигурация не меняются.

**Tech Stack:** Markdown, существующие команды Bun и Orval, Apidog Cloud Mock.

**Spec:** [Согласованный дизайн](../specs/2026-11-02-apidog-spec-first-design.md).

## Global Constraints

- Доработка самих моков и PR #121 в эту правку документации не входят.
- Новые скрипты, зависимости и CI-проверки не нужны.
- Подробный порядок и команды не дублируются во всех трёх файлах.
- Заглушки управляемых ответов в автоматических тестах сохраняются.
- Неготовность Go не блокирует разработку по согласованному контракту и Cloud Mock; поддержку старого API ради порядка выкладки не добавляем.

## Review Focus

Проверяется чтением итоговых документов по сценариям на шаге 4:

1. Операции нет в локальной спецификации: агент проверяет свежий Apidog, а не придумывает API.
2. Нет MCP: агент использует существующую выгрузку, при отсутствии доступа сообщает препятствие.
3. Выбрана другая ветка: контракт и Cloud Mock относятся к одной ветке; по умолчанию main.
4. Мок возвращает неверное тело или не покрывает ошибку: сначала отдельный MR в Apidog и повторная проверка после слияния.
5. Сценарию нужно состояние Go: управляемые ответы в тестах допустимы, проверка реального Go остаётся отдельной интеграционной проверкой.
